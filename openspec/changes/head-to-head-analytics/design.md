# Design
React route /comparacoes, two searchable selectors, mode direct/overall, inclusive season range, phase selector, six tabs (overview, offense, defense, history, seasons, achievements). Preserve approved shell and palette; keyboard access and mobile layout. URL query parameters preserve filters.
BFF GET /api/comparisons/teams?teamA={uuid}&teamB={uuid}&fromSeason=...&toSeason=...&phase=all&mode=direct; history endpoint /api/comparisons/teams/games with cursor and limit 1–100. API validates IDs, distinct teams, range and enums; 400 invalid, 404 unknown, 503 unavailable. Response includes mode, filters, games, per-team metrics, metric coverage (eligible/observed), source references, asOf, revision, partial flag. No games returns zero counts and null averages. Overall mode returns separate denominators; no shared encounter count implied. Achievements use separate season-filtered title facts, explicitly independent of direct match filters.
Application query handler uses ITeamComparisonReadRepository; PostgreSQL implementation queries canonical final games and game-team facts in consistent read transaction. Start with indexed SQL; benchmark before materialized views. Optional projections keyed by unordered franchise pair, season and disjoint phase, with revision; reverse presentation on swapped input. Never sum averages or streaks; derive from ordered games or sufficient aggregates. Cache key includes all filters and revision. No cross-store joins. Correction invalidates affected projections and cache. History order kickoff/date then game ID; uncertain historical dates flagged, not fabricated. Target p95 <= 500 ms API for warm indexed comparison, provisional pending benchmark. Tests use synthetic fixtures only.
