# Design — ADR-001 revision
HistoricalCollector uses bounded dataset/season partitions and resumable cursors; IncrementalCollector uses provider revision/watermark with overlap and periodic reconciliation. Both use HttpClient, bounded CSV/gzip parsing, SHA-256 and approved provider configuration. Validate licensing and schemas before production.
Pipeline: fetch -> immutable object upload/checksum verification -> register manifest -> parse/stage -> resolve external IDs -> validate/quarantine -> transactional upsert canonical facts and checkpoint/outbox -> analytics refresh -> publish revision. Object storage and PostgreSQL are not a distributed transaction: retry by deterministic object key, reconcile orphan objects, never advance checkpoint before canonical commit. Separate fetch and publish checkpoints. Use dataset/partition lease or PostgreSQL advisory lock (not implemented yet); bounded retries with jitter and Retry-After, cancellation, failure isolation and audit.
Quality/Reconciliation validates distinct teams, scores, phases, season membership, conflicting sources and missing metrics; unresolved conflicts quarantine for review. Corrections preserve revision history and invalidate affected projections. StatisticsAggregator, HeadToHead and Records workers consume idempotent outbox events; compute SQL/C# metrics, never AI arithmetic. Archive worker verifies raw object retention and backups; never deletes canonical games by season. MongoDB editorial/research documents reference canonical IDs, with source and review status; no cross-store join in comparison path.
Existing snapshot bytea storage remains until object migration is verified; migrate copy/checksum/manifest/read verification before approved cleanup. Existing AI contracts are not running AI agents. AI proposals require evidence and human approval. API/BFF reads normalized approved records. Schedules configurable; backfill throttled independently from incremental jobs. Monitor lag, failures, bytes, coverage, conflicts and projection revision.
